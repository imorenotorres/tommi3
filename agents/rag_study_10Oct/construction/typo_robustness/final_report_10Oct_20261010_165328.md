## 4. Typo Robustness Strategies (RQ3)

### 4.1 Design

Base agent: **llm_A_std** (74.0% on typo set, chosen as representative std-only agent).
Evaluation: evaluation_set_typo.json (77 queries).

### 4.4 Analysis

**V1 and V3 achieve the same gain (+9.1%)** at identical cost (1 API call/query).

- **V1 (Explicit instruction)** is the simplest intervention: one added paragraph in the prompt.
  It most improves `topic` (+30 pp) and `project` (+30 pp).
  Introduces some new errors in `papers` (−10 pp vs baseline).

- **V2 (Preprocessing)** underperforms despite double the API cost.
  The spell-correction step does not always improve the query and can introduce its own errors.
  Net result: 5.2% gain, lower than V1/V3.

- **V3 (Few-shot)** matches V1 overall but distributes gains more evenly.
  Best for `papers` (+10 pp vs baseline) and `organization` (+20 pp).
  Slightly worse than V1 on `topic`.

**Persistent failure across all approaches: `general`** (62%) — queries about non-RAI topics
(blockchain, vaccines, IoT) with heavy typos are still confused with `glossary` or `out_of_scope`.

## 5. Summary and Conclusions

| RQ | Finding | Strength |
|----|---------|---------|
| **RQ1a** | Phrasing complexity (T2/T3) has small, inconsistent effect on accuracy (−1 to −5%) | Weak / inconclusive |
| **RQ1b** | Typo errors cause consistent −7 to −11% accuracy drop; grammar errors negligible | Strong for typo |
| **RQ2** | AACP training on variant queries does not improve L2 robustness (Δ ≈ 0%) | Clear null result |
| **RQ3** | Explicit instruction or few-shot examples recover +9.1% accuracy on typo set | Strong, practical |

### Key Takeaways

1. **LLMs are moderately vulnerable to orthographic noise** (L1 Spanish typos), but not to grammatical interference from the same L1.

2. **Automated prompt construction (AACP) cannot overcome this vulnerability** — even when typo variants are included in the development set. The meta-LLM learns category disambiguation, not noise robustness.

3. **Simple prompt engineering works**: a single explicit noise-handling instruction or 10 few-shot examples recovers most of the lost accuracy (+9.1 pp), at no extra infrastructure cost.

4. **Preprocessing (spell correction) is not recommended**: higher cost, lower gain, introduces new error sources.

5. **Persistent challenge**: the `general` category (non-RAI research topics with typos) remains the hardest to classify reliably across all strategies.
